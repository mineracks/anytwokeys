How what leaves is costed
Silent payments
Payments to the wallet's sp1… address are taproot outputs no exported key can see: the sender derives each from their own inputs. The scan key finds them — it can read every payment ever made to this wallet and cannot spend one — and it stays sealed on this computer. Each block is read once; a refresh reads the new ones.
If this wallet also receives silent payments (it has an sp1… address), those coins are taproot outputs its exported key cannot see: the sender derives each one from their own inputs. Finding them needs the wallet's scan key — a key that can read every payment ever made to it, and cannot spend one. Enter the seed words once: the app checks they are this wallet's by the account key they give, keeps the scan key sealed on this computer, and keeps nothing else.
Seed words unlock everything that wallet can spend. They are used once, here, to derive the scan key and the spend public key, then cleared. Do this only on a computer you trust with that wallet.

Where it looks
A vault belongs to the network it was made on and cannot be moved to another. The servers come from App settings, and apply to every vault on this network.
Can this vault still be recovered?
A drill rebuilds this vault from the cards themselves — each with its own PIN, exactly as a real recovery would — and checks that what comes back is this vault and derives the same addresses. It reads the cards only. Nothing is spent, nothing is written to the chain, and the vault is not changed.
The recovery line
The descriptor that rebuilds this vault's addresses. It can watch, and it cannot spend — but it shows whoever reads it everything this vault holds and has done, so it stays hidden until you ask.
Split it into shares
For metal plates or paper kept apart: the recovery line split so that any few of the shares rebuild it, and fewer say nothing about this vault. SSKR, the Blockchain Commons standard.

    How to make a read-only rune
    On the machine that runs Core Lightning — an Umbrel, a Start9, a RaspiBlitz, or a server — one command makes a rune that can list and read, and nothing else. Copy it, run it, and paste what it prints into the box above. It is the only thing the node ever hands this app.
    lightning-cli createrune restrictions='[["method=getinfo","method=listfunds","method=listpeerchannels","method=listclosedchannels","method=listinvoices","method=listpays","method=listsendpays","method=listtransactions","method=listforwards","method=bkpr-listaccountevents","method=bkpr-listincome","method=bkpr-listbalances","method=checkrune","method=decode"]]'
    On Umbrel: docker exec core-lightning_lightningd_1 lightning-cli createrune … On Start9 the Core Lightning service page has a REST address and lets you make runes under Properties. The address is where clnrest answers: on Umbrel and Start9 it is on the service page; on a server it is the clnrest-host and clnrest-port lines in your config. A rune made for another app, or the admin rune, is refused here.
    How to make a read-only macaroon
    On the machine that runs LND, one command bakes a macaroon that can read and nothing else. Paste what it prints (hex) into the box above. An lndconnect:// link from your node’s UI also pastes here and fills in the address and certificate — but one carrying the admin macaroon is refused, since that one can spend.
    lncli bakemacaroon info:read onchain:read offchain:read invoices:read macaroon:read
    On Umbrel: docker exec lightning_lnd_1 lncli …; on RaspiBlitz, lncli is already on the path; on Start9 the LND service page shows the REST address and lets you make a read-only macaroon under Properties. The address is where REST answers, usually https://host:8080. The first check shows the certificate the node answered with; it is remembered from then on.

      This is the taxpayer's rule, so it is set once here. The UK does not allow a choice at all (it pools every wallet together, with same-day and 30-day rules this app does not compute). These are facts about what coins cost and were worth, not a tax position; an accountant decides how they are reported.
      Proving a vault can be recovered
      A drill rebuilds a vault from its own cards and checks the result really is that vault. A key that has died, been wiped, or had its PIN locked out fails silently — nothing tells you until the day you need it, which is the day it is too late. The reminder is a quiet line on that vault's Home, and it never blocks anything.

      Coins

      Working offline
      Work offline
      Nothing leaves Any Two Keys while this is on: not the node, prices, your labels, the maps or place search. You can still open the app, read everything in it, build a spend and sign it with your keys — only sending a signed spend on needs the network. This is this app's own promise and nothing more: it does not speak for anything else running on the computer.

      One key means no way back

      A single-key vault has exactly one copy of its private key, inside one YubiKey. There is no seed phrase and no backup. If that key is lost, damaged, wiped or its PIN is locked, the funds are gone for good.
      Use it only for amounts you would be willing to lose. For anything else, a 2-of-3 vault survives the loss of a key.
